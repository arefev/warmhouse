### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать/выключать отопление в своих домах.
- Чтобы подключить дом необходимо вызвать специалиста по подключению системы отопления

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс

### 2. Анализ архитектуры монолитного приложения

- Язык программирования: Go
- База данных: PostgreSQL
- Архитектура: монолитная, все компоненты (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения
- Взаимодействие: синхронное, запрос обрабатываются последовательно.
- Масштабируемость: ограничена, так как монолит сложно масштабировать по частям.
- Равертывание: требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

- Домен управления пользователями системы
  - поддомен управления пользователями
    - контекст: регистрация пользователя
	- контекст: аутентификация / авторизация пользователя
- Домен управления устройствами в доме
  - поддомен управления отоплением
    - контекст: включение/выключение отопления в доме
  - поддомен мониторинга температуры
    - контекст: отображение текущей температуры в доме

### **4. Проблемы монолитного решения**

- Нет возможности подключать новые датчики к умному дому
- Нет возможности реактивного получения данных о состоянии датчиков в доме.
- Планируется увеличение кол-ва пользователей системы, будут трудности с масштабированием.
- При выпуске релизов необходимо оставновить приложение целиком.
